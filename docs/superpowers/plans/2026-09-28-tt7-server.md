## Goal
The server side of SPEC.md §39–40. One process manages any number of tt7 panels. Each panel shows a web page (any URL), rendered by headless Chrome and pushed as PNG frames. Touches on the glass become clicks in that page.

## Design
```text
screens.toml ──► tt7-server (Go, one binary)
                   │ per screen:
                   │   headless Chrome tab, 1280×800, at screen.url
                   │   page changes → screenshot PNG → PUT /api/v1/frame (only when pixels change)
                   │   every 60 s → POST /api/v1/heartbeat (keeps the fallback clock away)
                   │   WS /api/v1/events ──► touch down/move/up → mouse press/move/release at (x, y) in the tab
                   │   reconnect with backoff; re-push the current frame when a panel comes back or reboots
                   └ admin: web page + JSON API (screens, status, assign URL, reload, preview)
```
- **Change detection:** CDP `Page.startScreencast` emits frames only when the page repaints. Fall back to polling screenshots with a hash if screencast misbehaves headless. Verified in S1: screencast works headless here and polling would repaint the page on every capture, so screencast it is (server/README.md has the evidence).
- **Frame format:** the panel's v1 takes PNG only (tt7d `PUT /api/v1/frame`), 1280×800 exactly, with the Bearer token and `X-Frame-ID`.
- **Touch:** tt7d events carry logical x/y (already rotated) plus `frame_id`. Map them to CDP `Input.dispatchMouseEvent` (pressed/moved/released, left button). Log a touch whose frame_id isn't the latest pushed one, but still deliver it.
- **Buttons** (power/volume): logged only in S1 (YAGNI).
- **Config** `screens.toml`: a `[[screen]]` table with `name`, `host` (IP[:port]), `token_file`, `url`, and optional `enabled`, `heartbeat_s`. Server-level: `listen` (admin; default 127.0.0.1), `chrome_path`, `chrome_flags` (this box needs `--no-sandbox`, see gotchas.md), `admin_token_file`.
- **Admin:** a small HTML page plus `GET /api/screens`, `PUT /api/screens/{name}/url`, `POST /api/screens/{name}/reload`, `GET /api/screens/{name}/preview.png`. Loopback by default; a token when bound elsewhere.

## Tests
- Unit: config parsing and validation, frame change detection, the touch→mouse mapping, backoff.
- **E2E with real panels-in-a-box:** start 2 host-built `tt7d` daemons (file-backed fb, fixture sysfs, input FIFOs: the same harness as `tt7d/test_*_e2e.py`) plus real headless Chrome and a local test HTML page with a counter button. Assert: each fb shows its page (pixels); a click via a touch written into a daemon's input FIFO increments the counter on the right screen only; a daemon restart gets the frame re-pushed; heartbeats keep `fallback.active=false`. No mocks of the logic under test.
